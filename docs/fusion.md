# Fusion 与 Plan

## 新建 Fusion 会话

在「设置 → Fusion」选择主模型、工作模型池、轻量模型，以及专家任务次数、已知 Token 和单个专家运行时间上限。然后在新会话输入框下方选择「Fusion」再发送。设置只影响之后新建的 Fusion 会话；普通会话不受影响。

主代理使用 WittyCode 自有 Harness 和选定的 ChatGPT Plan 或 API 模型。它负责判断任务、编写计划、选择是否委派、审查结果和最终验收。会话空闲时可通过输入框下方「更换主模型」明确确认，保留同一主代理、上下文、专家和预算；不会自行启动任务或静默回退。存在待审批计划时先处理计划，不能更换模型。工作专家使用池中模型，轻量专家使用指定的轻量模型；不会为保活定时调用。当前版本只接入自有模型适配，外部 ACP／CLI 尚未作为 Fusion 专家运行。独立的 Devin 或 Factory 会话行为不变。

专家任务串行执行，继承主会话的权限，必要时仍向用户询问。模块范围用于记录归属和复用上下文，**不是文件系统沙箱**；权限档位也不等于操作系统沙箱。主代理可以查看专家报告和保留的工具证据，仍需自行验证工作区。专家上下文保存在本地并只属于当前会话，重启后可复用；这不保证服务端缓存命中。主代理和专家按各自任务检索共享记忆，临时任务状态不会因 Fusion 自动写成长期记忆。

同一模块优先交给原专家。若专家中断或失败，先检查工作区和专家记录，再在专家面板明确允许继续；确认本身不会重做。用户也可以明确选择已授权的其他模型并确认转交：原记录保留，旧专家的上下文和证据在新专家首次接任务时按需交接。模型不可用、记录损坏或用量未知时不会静默换人或自动重放。

在会话下方的「授权模型」和「预算」中，可分别确认增加本会话的工作模型和上限，不会更改全局默认值，也不会自行启动任务。专家调用次数统计的是委派任务，不等于模型 API 请求次数；已知 Token 包含主代理、专家和摘要的报告用量。请求前会估算并预留，但**单次实际用量可能超过估算，不能承诺严格硬上限**。模型未报告用量或中断后费用无法确定时，自动请求会暂停；明确接受未知用量后可以继续，但历史总额仍可能未知。单个专家运行时间包含等待用户确认的时间。为避免未预算的旁路模型请求，Fusion 不自动生成会话标题或调用记忆整理模型。

## Plan 审批

在自有 Harness 会话中选择 Plan 后，主代理只读探索；Fusion 不在规划期间启动专家。主代理提交完整计划后，可以选择「继续修改」，或明确点击「执行方案」。审批只对当前计划版本有效；旧按钮、普通回复、切换模式和重启都不是批准。计划待确认时，排队消息会放回输入框；切到 Auto 后不能靠回复「继续」绕过审批，也不能切换到其他引擎。批准成功并保存后，才由同一主代理进入 Auto 执行，完整计划随执行请求传入。输入框有草稿或待发送附件时不能批准。

如果批准后在启动阶段中断，重新打开会保留计划并提示可能存在副作用；先检查，再重新明确决定。已经开始而结果未知的工作不会因重启自动重复。独立 ACP 会话不使用此审批流程。
