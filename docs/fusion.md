# Fusion 与 Plan

## 选择和配置 Fusion

在输入框的模型菜单选择「Fusion」，它是 WittyCode 分组下的普通模型项；已有会话空闲时可选择启用或退出，选择立即保留，下一次发送才实际应用。Fusion 行右侧的齿轮直达「设置 → Fusion」，可调整主模型、工作模型、轻量模型、各自思考等级、成本与质量倾向、专家运行时间和每次专家委派的步数范围。三个席位各固定一个模型选择框，右侧独立选择思考等级；工作模型不能增减，重复选择不会取消。配置修改在 Fusion 会话下一轮发送时应用，不打断当前运行；暂停的会话再次启用时也会检查新配置。更换主模型会先交接上下文，仅改专家模型或思考等级不会额外压缩主对话。只改主模型不改变会话内已有的工作／轻量角色授权，也不改变模型仍获授权的专家；V3 的 L1 入席专家则跟随主模型。在席位或角色的新配置下不再获授权的专家会保留旧记录，实际委派同一职责时才由对应席位或角色的新模型接续上下文和证据，不预建替补或自动启动专家。旧会话原有的预算上限仍保留。Fusion 输入栏不再重复显示思考等级，也不提供「更换主模型」「授权模型」快捷入口。

滑条给主代理提供相对权重，V3 记作本会话的成本–质量偏好 N（0–100）：偏成本时优先考虑较便宜的轻量席位，偏质量时更愿意使用工作席位和更充分的验证；它还移动工作项的派工阈值、决定争辩轮数和验收安排的严格程度。主代理仍根据任务难度、可能返工和已有专家上下文自行决定是否委派。权重不是模型价格，也不保证更高的结果质量或更低的费用，不保证模型严格遵循。新会话不设专家调用次数或 Token 固定上限，实际用量和费用可能增长；单个专家的运行时间限制仍然有效。

主代理可以选择 ChatGPT Plan、API、Devin ACP 或受控 Factory 模型，负责判断任务、编写计划、选择是否委派、审查结果和最终验收，不另设路由模型。会话中途启用或退出 Fusion 保留同一应用会话、历史、专家和已保存的配置；不会自行启动任务或静默回退。存在待审批计划、排队消息或目标任务时，不能手动切换普通模型或 Fusion 模式；全局 Fusion 配置可修改并等到新一轮边界应用。待审批计划仍由原主模型处理，不因配置更新绕过审批。V3 下专家按冻结工作项的席位使用指定模型：入座 L1 用主模型、L2 用工作模型、L3 用轻量模型；未冻结的只读委派按角色取工作或轻量模型；不会为保活定时调用。模型菜单遵循「账号与模型」中的显示开关；之前已选的模型不会因隐藏而被移除。四种后端都可以担任三个席位中的任意一席，并与其他来源混用。

专家按职能或工作项组织（如登录流程、图标制作），同一专家可以跨多个文件工作；Agents Team 显示该职责名称，不按单个改动文件拆人。无依赖且写入范围不重叠的专家任务可以并行，主代理可用 `delegate_tasks` 一次委派最多四项独立工作，四种主后端都支持；有依赖的工作仍需等待前置结果。同一专家不能同时接两轮任务，路径重叠或未声明写入范围时也不并发写入。仍带旧 Token 上限的会话保留串行预算保护。专家在右侧计划下方独立的 Agents Team 栏显示；无计划时仍可查看。当前活动专家在上，已完成、停止或失败的专家收在默认折叠的「历史专家」中，展开后按最近活动排序，支持鼠标和键盘操作。点开专家后，右侧检查面板上下分栏：上面是团队列表，不被下方内容挤压，超过面板高度约三分之一时自己滚动，标题行固定；下面是选中专家的工作记录，占满剩余高度并独立滚动，点另一位专家即切换。主代理写的任务书默认最多显示三行，可展开成限高的滚动区（整份任务书也是工作记录的第一条消息）。面板里每位专家显示累计 Token，标题汇总已知用量，选中的专家列出输入／输出／缓存明细；数字来自专家自己的会话，没打开时取会话账本里的记录，两者都没有就不显示。右栏的 Agents Team 标题下方有一张流程图：主代理到各专家的连线按状态流动或变色，滚轮缩放，中键拖动，点节点看工作记录；每位专家卡片左侧是一只按身份和状态变化的像素龙（见 `docs/knowledge.md`「Agents Team 流程图与像素龙」一条）。右栏左边缘可拖动，也支持聚焦分隔条后用左右键、Home／End 调整；释放时保存宽度，窄窗口自动限制可用宽度。Sub-Agent 动态继承主会话的权限档位和已有授权，完全访问不会再被降为写代码；受保护路径和 Plan 只读限制仍然生效，子代理获得的授权不反向扩大主代理权限。职责名称用于记录归属和复用上下文，文件／目录清单仅用于协调并发写入，**不是文件系统沙箱**；权限档位也不等于操作系统沙箱。主代理可以查看专家报告和保留的工具证据，仍需自行验证工作区。专家上下文保存在本地并只属于当前会话，重启后可复用；这不保证服务端缓存命中。主代理和专家按各自任务检索共享记忆，临时任务状态不会因 Fusion 自动写成长期记忆。

同一职责优先交给原专家，后续涉及的文件可以变化，不必另开专家。旧版按模块保存的专家和上下文仍可读取，不会删除或自动重放。若专家中断或失败，先检查工作区和专家记录，再在专家面板明确允许继续；确认本身不会重做。主代理也可检查证据后，用委派工具的 `resume: true` 明确发送新的下一步任务，继续复用该职责的上下文；省略此标记仍拒绝恢复，不会自动重放旧任务。用户也可以明确选择已授权的其他模型并确认转交：原记录保留，旧专家的上下文和证据在新专家首次接任务时按需交接。模型不可用、记录损坏或用量未知时不会静默换人或自动重放。

已存在的旧 Fusion 会话仍保留原有预算和「预算」入口，不会因升级而取消用户原先设置的上限：其 Token 限额按已报告用量和预估值检查，**单次实际用量可能超过估算，不能承诺严格硬上限**；用量未知时自动请求暂停，明确接受未知用量后才能继续。新会话没有这两个固定上限，用量未知不会因为预算而暂停。单个专家运行时间包含等待用户确认的时间。Fusion 不调用记忆整理模型。

新会话先用本轮选定的主模型（ChatGPT Plan、API、Devin ACP 或受控 Factory）和同一账号生成标题，更新会话名后才发送首条正文，不调用工作或轻量专家。标题请求只根据首条用户原文生成不超过 10 个字符的总结，不带附件内容，不进入对话历史。超时、失败或格式无效时自动重试 3 次；仍失败则正文和附件留在输入框，不允许通过手动改名跳过。旧未命名会话只在用户再次发言时用这次新输入尝试补名，不读取旧问题，也不会因打开会话或切换主模型而发送标题请求；旧会话仍带 Token 上限时在主回合结束后检查预算再尝试。若标题请求已发出却拿不到用量，仍按未知用量处理；若本地凭据检查明确拦在发送前，不记作未知用量。

模型参考缓存在 `%APPDATA%\WittyCode\fusion-profiles\models.json`，与 API Provider 的同名文件分开。指定自定义设置文件时，评分目录跟随设置文件的位置。每个模型 ID 只存 `score` 和 `cost`：优先采用 Artificial Analysis 的 Max 实测行；没有 Max 分数时，使用该模型有实测分的最高分行。`cost` 是榜单的每个基准任务美元成本，不是账单价格；实际使用的推理档位仍由 Fusion 席位配置决定。查不到的字段写 `null`，不再写 20 分占位。

新版启动后在后台合并旧档位记录，并主动刷新已存档及当前配置的模型。公共榜单只下载一次供本批匹配；断网或暂时查不到时保留已有实测参考。旧的独立 JSON 文件不删除。

## 固定路由

固定路由按 `docs/fusion-route-design-2026-11-18.md` 实现，只在底层，没有设置页。它分九个开关，写在设置文件的 `fusion_gates` 里：`drive`、`brief`、`report`、`route`、`acceptance`、`inject`、`map`、`observer`、`v3`。默认全开；把某一项设为 `false`，行为回到这个关卡之前。每任务度量没有开关，始终记录，只计数，不用来调整行为。

- **身份和任务书**（`brief`）：主代理委派时填身份（Coder、Runner、QualitySampler）、目标、约束、验收标准、写入范围和预算，不再填模型：V3 下写入委派的模型由冻结工作项的席位决定，未冻结的只读任务按身份角色取工作或轻量模型；身份决定工具与权限，不再决定模型。Runner 和 QualitySampler 没有编辑工具，每次新开会话；Coder 按职责复用。只读任务书不能编辑，也不能运行非只读命令。带身份的专家不能写长期记忆。身份文件放在 `%APPDATA%\WittyCode\configs\agents\`，同名文件覆盖内置身份，只能收紧权限。每次委派的步数有一组所有身份共享的最小/最大约束（「设置 → Fusion」，每侧默认勾选 Adaptive）：勾选的一侧由 Fusion 按任务规模计算，输入框灰底显示记住的数字——规模 = 不同写入路径数（≤8）+ 可辨认验收项数减一（≤7，按列表行计）+ 目标/验收文本每满 1000 字符一档（≤4），下限 = 16 + 4×规模（封顶 96；V3 下再按冻结工作项的风险指数加最多一半返工余量），上限 = 下限×2；最小任务得 16–32，例如 2 条路径、3 条验收项、短文 → 规模 4 → 32–64。取消勾选的一侧用手填数字（数字会记住），混合算出倒置时保留手动侧、调整自动侧。主代理请求的步数夹进该区间，全局单轮步数上限永远最后截断（低于下限时也以它为准）；只写秒预算的委派取有效上限；不带任务书的旧入口委派同样适用，按其路径和任务文本估规模；专家可提前交报告，区间不影响成本－质量滑条。生效步数及来源（Adaptive/手动、原请求值、全局截断）写进任务书和 Drive 的任务记录里，便于诊断。
- **运行超时**：「设置 → Fusion」的最长秒数默认 Adaptive。任务书可估秒数；未估时按生效步数 × 30 秒估算，至少 60 秒。Adaptive 不使用灰色数字作上限；手动模式以该数字为硬上限，任务书和计划只能缩短，每次运行均不超过 86400 秒。旧设置中已保存的有效秒数按手动模式读取，不改原文件。
- **回报**（`report`）：专家用 `submit_report` 结束任务，字段是状态、摘要、证据、笔记提议和评分。没交或有缺项时只补问一次，之后按未结构化接收。笔记是否进长期记忆由主代理决定。
- **路由**（`route`）：主代理在一个用户回合里第一次改动工作区之前要 `submit_route`，给出去向、理由和验证深度。没有路由时，编辑、非只读命令和写入委派被拒绝，读取和只读调研不受影响。已批准的计划可代替路由。
- **验收**（`acceptance`）：只对本次委派的无写入范围 Runner/QS 做自动恢复，不查找旧轮的待办、不重放作者或同批其他检查。超时加秒，步数用尽加步，临时中断或缺少证据时两者都加；每次最多翻倍，按手动、计划和安全上限截断。撞到上限不能扩大预算时停止，每次检查最多三次尝试。取消、账号/配置问题、权限拒绝和已有负面结论不通过重试来绕开。只有最后一次写入之后、运行正常且有证据的完成报告才算对应检查通过。委派过写入工作的回合，主代理给出最终回答时如果缺少路由和风险信号要求的检查，同一回合内补问一次；仍然缺，对话里提示「本轮工作未验证」。改动是否超出声明范围由程序对比工作区得出。
- **V3 派工与争辩**（`v3`）：路由可为每条写入职责冻结一项工作项——稳定 id、职责、角色、0..1 的得分 n_i（该项基于证据的难度/责任）和一句理由、冻结写入范围、依赖项 id、验收要点；首个写入委派前冻结，之后不能重打分、改名或改范围，同一职责加角色总是派回该项，依赖项未完成不开工，超出冻结范围的写入委派被拒绝。N 是本会话的成本–质量偏好（滑条 0–100），不是任务难度，也不是任务书字段：两道派工阈值沿固定有理曲线滑动，N=0 时约 0.91／0.95，N=50 时 0.30／0.85，N=100 时约 0.19／0.275；得分 ≤ 低阈进 L3 轻量席位、≥ 高阈进 L1 主席位、其间进 L2 工作席位，压线归声明席位（低阈 L3、高阈 L1）。席位只定政策模型和思考档位（L1 主、L2 工作、L3 轻量），工具权限仍归身份；入席专家只跑其席位模型。每个用户回合主代理先用 `declare_topic` 声明一次（simple 或 complex × discussion、plan、execute）；complex 且滑条高于 60 时跑一次只读 L1–L2 争辩——L2 席位挑最有分量的异议，L1 席位出 JSON 裁决，两席都无工具。默认轮数／硬上限按滑条分档：61–70 → 1/2、71–80 → 2/3、81–95 → 3/4、96–100 → 3/5，60 及以下不跑；达成结论提前结束，过默认轮数后只有新异议能续，撞上限如实报「未决」，同一议题累计轮数、改名不能重开。争辩只出讨论答案，不委派、不执行；Plan 下仍以提交计划等用户批准收尾，已批准的计划按版本继承 `submit_work_plan` 提交的工作计划；其中的事实与估算只在首个写入派工冻结前能重估。冻结项得分连同偏好折算风险指数：给自适应步数下限加最多一半返工余量，也决定验收时 Runner／QualitySampler 的安排；与最终状态一致的已有证据可顶替 Runner，但程序证据不等于用户验收。plan/execute 意图附团队模型档案快照：档案取自公开的 Artificial Analysis 排行榜，按（模型, 档位）缓存在本机；取不到时记中低能力估值、成本标未知，无档案如实标出；表中的每任务成本是外部参考值，不是用户的实际账单。
- **Fusion Drive**（`drive`）：每个项目一个本地库，在应用数据目录的 `fusion-drive` 下。任务书、回报、路由、裁决、Observer 报告和工具调用记录自动写入，代理用 `read_record` 按指针读一页。写入前密钥会被打码；疑似注入指令的记录不会被自动注入。
- **注入和评分**（`inject`）：专家开工时拿到按固定规则组装的注入包，上限 16K token，只含同一职责或路径重叠的记录。用到的记录必须评 −1、0 或 1，专家在回报里评，主代理用 `rate_records` 评；只读不评不会改变记录的质量分。Runner 不带项目的 `AGENTS.md`。
- **项目地图**（`map`）：一个项目第一次委派写入工作之前，主代理要调用 `choose_map_location`，由用户在提问卡片里选择把地图写进项目目录的 `.witty_map.md`，还是只存本机；跳过按只存本机处理。主代理用 `update_map_entry` 逐条补充。
- **Observer**（`observer`）：专家写出声明范围之外的文件，或同一调用连同相同结果连续三次，会在两次工具调用之间被暂停，报告交给主代理决定继续、改派或接手。判断型上报默认关闭（`fusion_observer_judgement`），关闭时不调用模型。

Drive 的设置也只在设置文件里：`fusion_drive_shared`（会话之间是否共用记录，默认关）、`fusion_drive_warm`（0.5）、`fusion_drive_keep_days`（7）、`fusion_drive_qk`（0.6）、`fusion_drive_auto_delete`（默认关）、`fusion_drive_max_gb`（5）。到达大小上限时先在提问卡片里问用户，确认后才清理；不确认就停止本会话向 Drive 写入，委派照常进行。

已知限制：应用没有永久删除会话的入口，会话的 Drive 记录不会随会话删除；评测（`evals/`）还不能跑 Fusion；这些关卡只用假模型测试过，没有用真实模型验证。

## 模型切换交接

选择模型只保存待切换目标，不发送压缩请求、不显示独立 `/compact` 回合，也不会弹回原模型。下一次按回车或点发送，消息和附件先从输入框移到对话底部，显示正在交接。原模型在后台压缩旧上下文，摘要保存后才切换，并把这条消息交给新模型一次。新模型收到摘要、重新读取的全局及项目 `AGENTS.md`，以及按最近用户意图检索的强相关记忆（遵循记忆启用与自动召回设置）；不是把整个记忆库或原始长历史重新塞入请求。原始历史和执行证据仍保留，跨引擎的附件仍由用户逐个选择。仅切换 Fusion 模式且主模型不变时，不额外请求摘要，但会更新模式指令。

压缩期间可停止；压缩失败、空摘要或停止都不切换模型、不发送用户消息，也不自动重放任务，保留历史、草稿及待切换目标。交接摘要须覆盖整个旧日志：未回答的旧用户消息只作为历史交给摘要模型，失败回合末尾的孤立思考不会发送。部分摘要或保存失败不会显示压缩成功；重试可复用已完成的摘要。待切换选择在重开会话后仍保留，不会自行发起请求。摘要消耗计入原模型用量。尚未发送消息的新分段可继续转交已有摘要，不重复包裹交接提示。独立 Devin／Factory 在原生上下文中请求摘要，临时收紧权限、拒绝审批及提问并检查工具活动；这不是操作系统沙箱，也不保证任意外部 CLI 会遵循摘要指令。Fusion 的 Devin 交接摘要使用同模型的独立受控 summarizer 会话，不加载原生工具，桥接工具清单也为空。

## Factory 席位的运行条件

发现 Factory CLI 与允许它接收 Fusion 消息是两件事。Windows 受控传输当前仅支持 1.18.0；需要现有权威机器策略只放行 Fusion 工具桥并禁用其他插件来源、`FACTORY_API_KEY`，以及不在任务工程或代理配置目录树中的本地私有临时区。不自动配置机器，不复用桌面登录。不能证实这些条件、模型/档位未确认、或工具清单不符时，拒绝发送，不退回独立 Factory、Plan 或其他后端。

每次请求新开一个受控席位：正文从宿主保存的压缩视图接续，工具经过 WittyCode 审批和证据检查点；标题、交接摘要及争辩使用无工具席位，不加载正文席位的工具。当前受控协议只发送文本，不能发送图片，也不能在有固定 Token 上限的旧会话中运行。测试的 4³ 组是**离线协议验收**，不是 64 次付费实测。运行 `tests/test_fusion_provider_matrix.py` 和 `tests/test_fusion_backend_contract.py` 时直接用默认前台托管入口，无需调整 TEMP。离线 Factory 替身把本次 `WITTYCODE_TEST_WORK` 当作虚拟机的根；从临时工作区到该根（含根）的目录配置、实际路径、DACL、钩子和工具清单照常校验。这个祖先范围只在替身测试内生效；生产仍检查到实际卷根。

## Devin ACP 的权限桥

标准 ACP 的权限请求是可选的，工具更新也是通知，不是执行前拦截。因此 Fusion 不把独立 Devin 会话的权限模式直接当作 WittyCode 权限，而是为每个主代理或专家单独启动受控 ACP 实例：

- 使用应用自有的空工作目录和独立配置，禁用原生文件、搜索、命令、子代理、权限升级与旁路 MCP 工具，关闭外部配置导入。Fusion 指令直接带上 `wittycode-fusion` 的工具名和参数索引，Devin 不必先查询完整清单即可用 `mcp_call_tool` 调用已注册的工具。需要详情时仍可用 `mcp_list_tools`；如果结果被截断，应回到索引，而不是用 Devin 原生 `get_output`。ACP 权限回调和执行前 hook 都校验目标，不允许查询所有服务器、调用其他服务器或访问 MCP 资源。切换用的摘要仍不允许调用任何工具。
- `SessionStart` hook 必须通过私有本机通道确认加载，之后才发送模型请求；所选模型和推理档位也须由 ACP 明确确认。缺少保护或不兼容的 CLI 会拒绝运行，不改用默认模型，也不退回原生工具。
- 私有 stdio MCP 只转发 WittyCode 的工具声明与执行。每次执行复用现有权限检查、审批／提问、Plan 只读限制、执行前持久检查点和完整输出保存；不接受 ACP 的永久授权或切换 bypass 选项。受保护路径和专家命令审批保持一致。临时通道凭据只放在子进程环境中，不写入配置或会话。
- 支持 `session/load` 的正式 Devin ACP 连接在工作结算后保留 5 分钟，不发保活请求。到期释放连接而不关闭标签页或删除专家；再次委派同一专家时恢复原生会话。标题与交接摘要使用独立临时连接，结束即释放。5 分钟是本地热保留时间，不保证服务端缓存命中。
- 原生会话 ID 与本地记录一起保存，恢复用 `session/load`，不靠它回放工具证据；证据实时保存在 WittyCode 的会话和完整输出存储中。中断、证据保存失败和未知工具尝试会停止本轮，不自动重放。主模型更换前完成压缩，旧 ACP 检查点保留为历史证据，新主模型从摘要建立上下文；专家不会因此被重新分配。超过提示长度的文字分块保留并提供 `read_output` 引用，不写入图片 base64 或加密思考内容，也不提高单份输出的 16 MiB 上限。

这是应用与兼容 CLI 的工具约束，**不是操作系统沙箱**；Devin hook 自身的异常处理也不构成 OS 隔离，原生 I/O 同时由独立配置的 deny 规则禁用。不要把任意 ACP 服务接入就声称具备同等保护。真实提供商和具体 CLI 版本的行为仍需兼容性验证；本仓库回归用本地假 ACP 进程与真实私有 MCP 工具桥，不调用真实模型。旧会话若仍有固定 Token 预算，ACP 会拒绝运行，避免把无法约束的远端用量假装成硬预算；请另建无固定上限的 Fusion 会话。

## Plan 审批

在自有 Harness 或 Fusion（包括 Devin 主代理）会话中选择 Plan 后，主代理只读探索；Fusion 不在规划期间启动专家。主代理提交完整计划后，可以选择「继续修改」，或明确点击「执行方案」。审批只对当前计划版本有效；旧按钮、普通回复、切换模式和重启都不是批准。计划待确认时，排队消息会放回输入框；切到 Auto 后不能靠回复「继续」绕过审批，也不能切换到其他引擎。批准成功并保存后，才由同一主代理进入 Auto 执行，完整计划随执行请求传入。输入框有草稿或待发送附件时不能批准。

如果批准后在启动阶段中断，重新打开会保留计划并提示可能存在副作用；先检查，再重新明确决定。已经开始而结果未知的工作不会因重启自动重复。独立 ACP 会话不使用此审批流程。
