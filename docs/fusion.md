# Fusion 与 Plan

## 新建 Fusion 会话

在「设置 → Fusion」选择主模型、工作模型池、轻量模型、成本与效率倾向，以及单个专家运行时间上限。然后在新会话输入框下方选择「Fusion」再发送。设置只影响之后新建的 Fusion 会话；普通会话不受影响。

滑条给主代理提供相对权重：偏成本时优先考虑较便宜的轻量模型，偏效率时更愿意使用工作模型；主代理仍根据任务难度、可能返工和已有专家上下文自行决定。权重不是模型价格或实际速度，也不保证模型严格遵循。新会话不设专家调用次数或 Token 固定上限，实际用量和费用可能增长；单个专家的运行时间限制仍然有效。

主代理可以选择 ChatGPT Plan、API 或 Devin ACP 模型，负责判断任务、编写计划、选择是否委派、审查结果和最终验收，不另设路由模型。会话空闲时可通过输入框下方「更换主模型」明确确认，保留同一主代理、上下文、专家和会话配置；不会自行启动任务或静默回退。存在待审批计划时先处理计划，不能更换模型。工作专家使用池中模型，轻量专家使用指定的轻量模型；不会为保活定时调用。模型菜单遵循「账号与模型」中的显示开关；之前已选的模型不会因隐藏而被移除。Devin 可以担任主代理或专家，并与其他来源混合使用；独立的 Devin 或 Factory 会话行为不变。

专家任务串行执行，继承主会话的权限；即使主会话为完全访问，专家的非只读命令仍需确认。模块范围用于记录归属和复用上下文，**不是文件系统沙箱**；权限档位也不等于操作系统沙箱。主代理可以查看专家报告和保留的工具证据，仍需自行验证工作区。专家上下文保存在本地并只属于当前会话，重启后可复用；这不保证服务端缓存命中。主代理和专家按各自任务检索共享记忆，临时任务状态不会因 Fusion 自动写成长期记忆。

同一模块优先交给原专家。若专家中断或失败，先检查工作区和专家记录，再在专家面板明确允许继续；确认本身不会重做。用户也可以明确选择已授权的其他模型并确认转交：原记录保留，旧专家的上下文和证据在新专家首次接任务时按需交接。模型不可用、记录损坏或用量未知时不会静默换人或自动重放。

在会话下方的「授权模型」中，可确认增加本会话的工作模型，不会更改全局默认值，也不会自行启动任务。已存在的旧 Fusion 会话仍保留原有预算和「预算」入口，不会因升级而取消用户原先设置的上限：其 Token 限额按已报告用量和预估值检查，**单次实际用量可能超过估算，不能承诺严格硬上限**；用量未知时自动请求暂停，明确接受未知用量后才能继续。新会话没有这两个固定上限，用量未知不会因为预算而暂停。单个专家运行时间包含等待用户确认的时间。Fusion 不自动生成会话标题或调用记忆整理模型。

## Devin ACP 的权限桥

标准 ACP 的权限请求是可选的，工具更新也是通知，不是执行前拦截。因此 Fusion 不把独立 Devin 会话的权限模式直接当作 WittyCode 权限，而是为每个主代理或专家单独启动受控 ACP 实例：

- 使用应用自有的空工作目录和独立配置，禁用原生文件、搜索、命令、子代理、权限升级与旁路 MCP 工具，关闭外部配置导入；原生执行前 hook 拒绝非私有工具桥调用。
- `SessionStart` hook 必须通过私有本机通道确认加载，之后才发送模型请求；所选模型和推理档位也须由 ACP 明确确认。缺少保护或不兼容的 CLI 会拒绝运行，不改用默认模型，也不退回原生工具。
- 私有 stdio MCP 只转发 WittyCode 的工具声明与执行。每次执行复用现有权限检查、审批／提问、Plan 只读限制、执行前持久检查点和完整输出保存；不接受 ACP 的永久授权或切换 bypass 选项。受保护路径和专家命令审批保持一致。临时通道凭据只放在子进程环境中，不写入配置或会话。
- 原生会话 ID 与本地记录一起保存，恢复用 `session/load`，不靠它回放工具证据；证据实时保存在 WittyCode 的会话和完整输出存储中。中断、证据保存失败和未知工具尝试会停止本轮，不自动重放。主模型更换时传入新产生的历史，保留原 ACP 上下文；超过提示长度的历史保留原文并提供 `read_output` 引用。

这是应用与兼容 CLI 的工具约束，**不是操作系统沙箱**；Devin hook 自身的异常处理也不构成 OS 隔离，原生 I/O 同时由独立配置的 deny 规则禁用。不要把任意 ACP 服务接入就声称具备同等保护。真实提供商和具体 CLI 版本的行为仍需兼容性验证；本仓库回归用本地假 ACP 进程与真实私有 MCP 工具桥，不调用真实模型。旧会话若仍有固定 Token 预算，ACP 会拒绝运行，避免把无法约束的远端用量假装成硬预算；请另建无固定上限的 Fusion 会话。

## Plan 审批

在自有 Harness 或 Fusion（包括 Devin 主代理）会话中选择 Plan 后，主代理只读探索；Fusion 不在规划期间启动专家。主代理提交完整计划后，可以选择「继续修改」，或明确点击「执行方案」。审批只对当前计划版本有效；旧按钮、普通回复、切换模式和重启都不是批准。计划待确认时，排队消息会放回输入框；切到 Auto 后不能靠回复「继续」绕过审批，也不能切换到其他引擎。批准成功并保存后，才由同一主代理进入 Auto 执行，完整计划随执行请求传入。输入框有草稿或待发送附件时不能批准。

如果批准后在启动阶段中断，重新打开会保留计划并提示可能存在副作用；先检查，再重新明确决定。已经开始而结果未知的工作不会因重启自动重复。独立 ACP 会话不使用此审批流程。
