# Fusion 与 Plan

## 选择和配置 Fusion

在输入框的模型菜单选择「Fusion」，它是 WittyCode 分组下的普通模型项；已有会话空闲时可选择启用或退出，选择立即保留，下一次发送才实际应用。Fusion 行右侧的齿轮直达「设置 → Fusion」，可调整主模型、工作模型、轻量模型、各自思考等级、成本与效率倾向和专家运行时间。三个角色各固定一个模型选择框，右侧独立选择思考等级；工作模型不能增减，重复选择不会取消。配置修改在 Fusion 会话下一轮发送时应用，不打断当前运行；暂停的会话再次启用时也会检查新配置。更换主模型会先交接上下文，仅改专家模型或思考等级不会额外压缩主对话。原专家记录保留，退出当前授权池的职责会转交给该角色的新模型，首次委派时交接上下文和证据；不因此自动启动专家。旧会话原有的预算上限仍保留。Fusion 输入栏不再重复显示思考等级，也不提供「更换主模型」「授权模型」快捷入口。

滑条给主代理提供相对权重：偏成本时优先考虑较便宜的轻量模型，偏效率时更愿意使用工作模型；主代理仍根据任务难度、可能返工和已有专家上下文自行决定。权重不是模型价格或实际速度，也不保证模型严格遵循。新会话不设专家调用次数或 Token 固定上限，实际用量和费用可能增长；单个专家的运行时间限制仍然有效。

主代理可以选择 ChatGPT Plan、API 或 Devin ACP 模型，负责判断任务、编写计划、选择是否委派、审查结果和最终验收，不另设路由模型。会话中途启用或退出 Fusion 保留同一应用会话、历史、专家和已保存的配置；不会自行启动任务或静默回退。存在待审批计划、排队消息或目标任务时，不能手动切换普通模型或 Fusion 模式；全局 Fusion 配置可修改并等到新一轮边界应用。待审批计划仍由原主模型处理，不因配置更新绕过审批。工作专家使用指定的工作模型，轻量专家使用指定的轻量模型；不会为保活定时调用。模型菜单遵循「账号与模型」中的显示开关；之前已选的模型不会因隐藏而被移除。Devin 可以担任主代理或专家，并与其他来源混合使用。

专家按职能或工作项组织（如登录流程、图标制作），同一专家可以跨多个文件工作；Agents Team 显示该职责名称，不按单个改动文件拆人。无依赖且写入范围不重叠的专家任务可以并行，主代理可用 `delegate_tasks` 一次委派最多四项独立工作，ChatGPT 与 Devin 主代理都支持；有依赖的工作仍需等待前置结果。同一专家不能同时接两轮任务，路径重叠或未声明写入范围时也不并发写入。仍带旧 Token 上限的会话保留串行预算保护。专家在右侧计划下方独立的 Agents Team 栏显示；无计划时仍可查看。当前活动专家在上，已完成、停止或失败的专家收在默认折叠的「历史专家」中，展开后按最近活动排序，支持鼠标和键盘操作。右栏左边缘可拖动，也支持聚焦分隔条后用左右键、Home／End 调整；释放时保存宽度，窄窗口自动限制可用宽度。Sub-Agent 动态继承主会话的权限档位和已有授权，完全访问不会再被降为写代码；受保护路径和 Plan 只读限制仍然生效，子代理获得的授权不反向扩大主代理权限。职责名称用于记录归属和复用上下文，文件／目录清单仅用于协调并发写入，**不是文件系统沙箱**；权限档位也不等于操作系统沙箱。主代理可以查看专家报告和保留的工具证据，仍需自行验证工作区。专家上下文保存在本地并只属于当前会话，重启后可复用；这不保证服务端缓存命中。主代理和专家按各自任务检索共享记忆，临时任务状态不会因 Fusion 自动写成长期记忆。

同一职责优先交给原专家，后续涉及的文件可以变化，不必另开专家。旧版按模块保存的专家和上下文仍可读取，不会删除或自动重放。若专家中断或失败，先检查工作区和专家记录，再在专家面板明确允许继续；确认本身不会重做。主代理也可检查证据后，用委派工具的 `resume: true` 明确发送新的下一步任务，继续复用该职责的上下文；省略此标记仍拒绝恢复，不会自动重放旧任务。用户也可以明确选择已授权的其他模型并确认转交：原记录保留，旧专家的上下文和证据在新专家首次接任务时按需交接。模型不可用、记录损坏或用量未知时不会静默换人或自动重放。

已存在的旧 Fusion 会话仍保留原有预算和「预算」入口，不会因升级而取消用户原先设置的上限：其 Token 限额按已报告用量和预估值检查，**单次实际用量可能超过估算，不能承诺严格硬上限**；用量未知时自动请求暂停，明确接受未知用量后才能继续。新会话没有这两个固定上限，用量未知不会因为预算而暂停。单个专家运行时间包含等待用户确认的时间。Fusion 不自动生成会话标题或调用记忆整理模型。

## 模型切换交接

选择模型只保存待切换目标，不发送压缩请求、不显示独立 `/compact` 回合，也不会弹回原模型。下一次发送时，先由原模型压缩当前上下文，摘要成功且可保存后才切换，并将这条消息发送一次。新模型收到摘要、重新读取的全局及项目 `AGENTS.md`，以及按最近用户意图检索的强相关记忆（遵循记忆启用与自动召回设置）；不是把整个记忆库或原始长历史重新塞入请求。原始历史和执行证据仍保留，跨引擎的附件仍由用户逐个选择。仅切换 Fusion 模式且主模型不变时，不额外请求摘要，但会更新模式指令。

压缩期间可停止；压缩失败、空摘要或停止都不切换模型、不发送用户消息，也不自动重放任务，保留历史、草稿及待切换目标。交接摘要须覆盖整个旧日志：未回答的旧用户消息只作为历史交给摘要模型，失败回合末尾的孤立思考不会发送。部分摘要或保存失败不会显示压缩成功；重试可复用已完成的摘要。待切换选择在重开会话后仍保留，不会自行发起请求。摘要消耗计入原模型用量。尚未发送消息的新分段可继续转交已有摘要，不重复包裹交接提示。独立 Devin／Factory 在原生上下文中请求摘要，临时收紧权限、拒绝审批及提问并检查工具活动；这不是操作系统沙箱，也不保证任意外部 CLI 会遵循摘要指令。Fusion 的 Devin 交接摘要使用同模型的独立受控 summarizer 会话，不加载原生工具，桥接工具清单也为空。

## Devin ACP 的权限桥

标准 ACP 的权限请求是可选的，工具更新也是通知，不是执行前拦截。因此 Fusion 不把独立 Devin 会话的权限模式直接当作 WittyCode 权限，而是为每个主代理或专家单独启动受控 ACP 实例：

- 使用应用自有的空工作目录和独立配置，禁用原生文件、搜索、命令、子代理、权限升级与旁路 MCP 工具，关闭外部配置导入；原生执行前 hook 拒绝非私有工具桥调用。
- `SessionStart` hook 必须通过私有本机通道确认加载，之后才发送模型请求；所选模型和推理档位也须由 ACP 明确确认。缺少保护或不兼容的 CLI 会拒绝运行，不改用默认模型，也不退回原生工具。
- 私有 stdio MCP 只转发 WittyCode 的工具声明与执行。每次执行复用现有权限检查、审批／提问、Plan 只读限制、执行前持久检查点和完整输出保存；不接受 ACP 的永久授权或切换 bypass 选项。受保护路径和专家命令审批保持一致。临时通道凭据只放在子进程环境中，不写入配置或会话。
- 原生会话 ID 与本地记录一起保存，恢复用 `session/load`，不靠它回放工具证据；证据实时保存在 WittyCode 的会话和完整输出存储中。中断、证据保存失败和未知工具尝试会停止本轮，不自动重放。主模型更换前完成压缩，旧 ACP 检查点保留为历史证据，新主模型从摘要建立上下文；专家不会因此被重新分配。超过提示长度的文字分块保留并提供 `read_output` 引用，不写入图片 base64 或加密思考内容，也不提高单份输出的 16 MiB 上限。

这是应用与兼容 CLI 的工具约束，**不是操作系统沙箱**；Devin hook 自身的异常处理也不构成 OS 隔离，原生 I/O 同时由独立配置的 deny 规则禁用。不要把任意 ACP 服务接入就声称具备同等保护。真实提供商和具体 CLI 版本的行为仍需兼容性验证；本仓库回归用本地假 ACP 进程与真实私有 MCP 工具桥，不调用真实模型。旧会话若仍有固定 Token 预算，ACP 会拒绝运行，避免把无法约束的远端用量假装成硬预算；请另建无固定上限的 Fusion 会话。

## Plan 审批

在自有 Harness 或 Fusion（包括 Devin 主代理）会话中选择 Plan 后，主代理只读探索；Fusion 不在规划期间启动专家。主代理提交完整计划后，可以选择「继续修改」，或明确点击「执行方案」。审批只对当前计划版本有效；旧按钮、普通回复、切换模式和重启都不是批准。计划待确认时，排队消息会放回输入框；切到 Auto 后不能靠回复「继续」绕过审批，也不能切换到其他引擎。批准成功并保存后，才由同一主代理进入 Auto 执行，完整计划随执行请求传入。输入框有草稿或待发送附件时不能批准。

如果批准后在启动阶段中断，重新打开会保留计划并提示可能存在副作用；先检查，再重新明确决定。已经开始而结果未知的工作不会因重启自动重复。独立 ACP 会话不使用此审批流程。
