## 修复方案

按依赖排序。每一批单独提交，先写会失败的测试再改。

### 第 1 批：权限判定（S1、S2）

- 按本地文件里记的修法改，里面列的每条复现都成为回归测试，再补一轮变异测试。修复和测试一起提交，之后把细节补进本文。

### 第 2 批：模型看到的内容要和工具说的一致（T1、V1、L4）

- `read_file` 的一页不超过循环的结果上限，按字符分页，页脚写清「显示第 a–b 行，接着读用 offset=…」。
- 循环不再对自己分页的工具做无声的中间截断；必须截断时写明缺的是哪些行或哪一段，并告诉模型怎么取回。
- 被忽略的参数名写进结果里告诉模型；整数形式的字符串接受为整数。
- 只有推理、没有文字也没有调用的回答：提示模型一次让它给出回答，仍然为空就告诉用户。

### 第 3 批：请求不该白发（L1、O1 的超时与 401）

- 连接超时和读超时分开（连接 15–20 秒）。
- 服务端一旦返回过任何事件（包括 `response.created`），就算「已开始」：读超时不再当成连不上去盲目重发；告诉用户「模型长时间没有输出」，最多重试一次并写明。
- 读超时按推理档位放宽；先用真实探针量出高档位下流里最长的静默时间。
- 401 且刷新令牌还在时，强制续期一次再发。

### 第 4 批：Anthropic 路线（A1、A2）

- 按模型能力选思考写法：支持自适应的模型发 `thinking: {"type": "adaptive"}` 加 `output_config.effort`，只有旧模型才发预算。Bedrock 的两条路径同样处理。
- 思考块只要有签名就保留并原样带回，文字为空也一样。
- 用假服务补测试；**需要一把真实的 Anthropic 密钥做几次小请求**才能算验证过。

### 第 5 批：用量与可观测性（U1，缓存文档的阶段 0、1）

- 读 Cache Write 并让存档带上它，两处一起改。
- 保留响应里的诊断字段；每个请求记一条只含数字和哈希的记录。
- 保留助手消息的 `phase`；重放改成原样保留。

### 第 6 批：省钱（P1a、C1、C2）

- 指令快照加追加式更新（缓存文档的阶段 2）。
- 压缩阈值加一条「价格分界」：模型有长上下文价时，默认在分界之前压缩，用户可以改。
- 压缩时把最新的清单原样带过去；编辑类调用的参数放宽截断；摘要请求放得下时复用主前缀。

### 第 7 批：搜索与并行（T2、L2）

- 在 Git 仓库里，`grep` 和 `glob` 的文件清单取自 `git ls-files --cached --others --exclude-standard`（只读、不触发仓库程序的调用方式，沿用现有的 Git 中和环境）；不在仓库里时退回现在的遍历。
- 超时的报错按实际原因写：是文件太多还是正则在回溯，各给各的建议；先列出搜了多少文件。
- 同一步里连续的、判定为放行的只读调用并发执行，结果仍按原顺序追加；要问用户的和会改东西的保持串行。

### 第 8 批：健壮性（L3、M1、T3、T4、M2）

- 流中断时先把已完成的输出项提交进历史，再标记失败。
- 记忆服务器死了就重启一次并告诉用户；工具声明不随连接状态变化。
- 文件工具识别 GB18030（和侧栏预览同一套判断），读、搜、改都保持原编码。
- `create_file` 覆盖已有文件前，要求本会话读过它且之后没有被别人改过，否则让模型先读；覆盖时保留原来的 BOM 和换行。
- MCP：翻页，非文字结果给出说明，停止时通知服务器，错误输出进日志。

### 第 9 批：能力（T5、G1、O1 其余）

- 后台命令：启动、看输出、结束三个动作，受同样的权限判定；放宽单条命令的上限。
- 长输出落盘，结果里给出文件位置，模型可以分页读。
- `edit_file` 一次调用接受多处修改。
- `/goal` 的总预算、来回转圈的重复调用检测、旧图片在压缩时换成一句话。
- 联网工具和用户自己的 MCP 服务器：先由用户决定要不要做。
