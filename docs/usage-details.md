# 使用细节

[`README.md`](../README.md) 讲 WittyCode 是什么、怎么装；这里是细节：启动与设置的零碎、离线回放、会话控件、换引擎时带什么、附件的限制、窗口的边界。下面有些段落写于只有 Droid 的时候，说「Droid」的地方，对 Codex、Devin、ChatGPT Plan 一样适用，除非另有说明。

## 启动与设置的零碎

- 凭据：Factory、Codex、Devin 的凭据由它们各自的程序管理，WittyCode 不读取、不保存。ChatGPT Plan 的登录凭据保存在 `%APPDATA%\WittyCode\chatgpt\`，只用来调用 OpenAI。
- 找 `droid.exe`：先看设置里的 `droid_path`，再看环境变量 `WITTYCODE_DROID_EXECUTABLE`，再找 Factory 桌面版自带的，最后找 `PATH`。**没装 Factory 也没指定路径时不算错误**，启动时不提示，只是菜单里没有 Factory 的模型；指定了路径但文件不存在才会提示。
- 日志在 `%APPDATA%\WittyCode\WittyCode.log`（用了 `--settings` 就在那个设置文件旁边）。没有控制台的进程无处打印错误，所以用 `WittyCode.pyw` 启动失败时会弹出消息框。
- 从旧名字升级（应用原名 droid-desk）：旧启动文件 `droid-desk.pyw` 已删除，快捷方式要指向 `WittyCode.pyw`。第一次启动会把 `%APPDATA%\droid-desk\settings.json` **复制**到 `%APPDATA%\WittyCode\settings.json`（只复制一次：旧文件不移动、不删除，新位置已有设置时不覆盖）。
- 没有控制台的进程启动 `droid.exe`（一个控制台程序）时，Windows 会为它开一个控制台窗口。WittyCode 启动 droid 时加了 `CREATE_NO_WINDOW`（`desktop/core/winproc.py`），并在 `pythonw.exe` 下用真 droid 验证过：整个过程里 droid、它的控制台宿主、它启动的 PowerShell 都没有可见窗口；关掉这个补丁后同一脚本会看到一个整屏大小的 Windows Terminal 窗口（见 `docs/phase1.md` 第 5 节）。只在一台机器上验证过，它的默认终端是 Windows Terminal。

## 不花钱试一下

回放 Phase 0 录下的真实事件流，不启动 droid，也不调用模型：

```powershell
.\.venv\Scripts\python.exe -m desktop --replay fixtures\stream_turn.jsonl --speed 20
```

窗口打开后：加一个文件夹（或在命令行里加 `--project .`）、点「新会话」、随便发一条消息，就会回放录制里的下一轮；回放里的权限卡片同样要点击才会继续。录制用完之后，再发消息只会得到一句提示。其他可回放的录制：`ask_user.jsonl`、`interrupt.jsonl`、`interrupt_running_tool.jsonl`、`resume.jsonl`。回放模式也能试附件：回放不看你发的内容，但附件的添加、缩略图和对话里的显示都是真的。

## 会话控件与上下文

模型、推理强度、权限级别和 Auto/Plan 模式在输入框下方的一排小下拉框里（顶部没有工具栏）。它们跟随当前标签页里 Droid 实际在用的值（Droid 可能替换掉无效的模型 id，控件会跟着变）；改动立刻作用于当前会话，同时保存为新会话的默认值。

状态栏在累计用量左边显示上下文用量：`上下文 13K / 197K` 表示「这次会话发给模型的内容（系统提示、工具说明和全部对话）」约 13K token，模型的上下文窗口是 197K；斜线后面跟着模型走，还不知道的显示 `—`。鼠标悬停有逐项解释，包括 Droid 自动压缩对话的阈值（实际能用到的往往比窗口小）。

### 会话名字与阅读位置

发出首条问题后，WittyCode 会让 LLM 总结一个短标题，不再直接截取第一句话。摘要独立进行，不阻塞当前回答；会消耗所选来源的额外用量。手动重命名始终优先，摘要失败时保留中性名字，不自动批量修改旧会话的标题。

左侧短标记用于回合快速跳转。切换已打开的会话时，各自恢复之前的历史阅读位置，或继续跟随最新；多行输入不会挪动导航。阅读位置只在本次打开期间保留，关闭标签或重启应用后不承诺恢复。

### 在 WittyHarness、Devin、Factory 之间换模型时带过去什么

**在 WittyCode 中始终是同一个会话和侧栏行**，并保留原来的名字、创建时间、排序及累计用量；关闭、重新打开和重启也沿用这个关联。底层引擎仍各存自己的原生分段，WittyCode 保存它们之间的关联和完整阅读记录，不修改外部引擎的历史。没有可靠关联的旧同名会话不会被猜测合并。

两边的模型互相读不到原生会话，所以换到另一边的模型时，WittyCode 把这个对话里之前的**文字**（你的消息和助手的回答）放在下一条消息前面交给新模型；工具调用和结果、思考不带给模型，但仍保留在 WittyCode 的阅读记录中。

- 带多少跟着新模型的上下文窗口走：窗口的 10%，在 64 KiB 到 256 KiB 之间，新的优先；窗口还不知道时按 64 KiB。太长的单条消息只带开头，状态栏和对话里会说明有几条被截、更早的被省略。
- **附件由你一个一个选，WittyCode 不替你决定。** 对话里只要有附件（文本文件、图片、PDF，包括没有文字的扫描 PDF），切换前都会弹出一个清单，每个附件一个勾选框，默认一个都没勾：勾上的带过去，没勾的留在这里。点「取消」或按 `Esc` 什么都不会发生；一个都不勾就点「都不带，换过去」；`Enter` 不会替你确认。
  - 文本文件和能提取出文字的 PDF：文字跟在它所属的消息后面一起交给新模型，计入同一个预算，会多用一些输入 token。
  - 图片和没有文字的 PDF：作为文件随换过去之后的第一条消息一起发出（发出去之前输入框的提示会写「和 N 个附件」）。
  - 新模型带不了的（比如 Codex 读不了没有文字的 PDF、模型不支持图片、从已保存的会话里恢复的图片已经没有内容）照样列在清单里，灰着不能勾，旁边写明原因，不会悄悄省掉。
  - 一条消息通常带 10 个附件文件（图片、没有文字的 PDF）、合计 20 MB 以内。勾得比这多也可以：清单会写明**超了多少**，「换过去」按钮改成「超出了，仍然带上选中的 N 个，换过去」，由你决定，程序不会替你少带。输入框里已有的附件也算在这条消息里。只有多到 50 个或 200 MB（多半是误拖了一个文件夹）才会拒绝。
- 换过去之后第一条消息的缓存是冷的，会比平时多花一些。

### 选择在对话页显示哪些模型

模型菜单里的模型太多时，可以在「设置 → 账号与模型」里挑：Factory 卡片、Codex 订阅卡片和每个 API Provider 下面各有一个折叠的「对话页显示的模型」列表，每个模型一个开关，另有「全部显示 / 全部隐藏」。关掉的模型不再出现在输入框下面的模型菜单里（Factory 的按厂商分组，和菜单一致）。

- 正在使用的模型照常显示，菜单里注明「已在设置里隐藏，正在使用所以还显示」，不会让当前会话的模型凭空消失。
- 一个来源的模型全部隐藏时，菜单里这一组留着标题并写「没有显示的模型」，指向设置。
- 「新会话默认值」选中的模型被隐藏后，新会话改用第一个还显示的 Factory 模型（设置里记着的选择不丢，重新显示就恢复）。
- 隐藏只影响菜单，不影响已有的会话；列表按模型 id 记在 `settings.json` 的 `hidden_models`，模型暂时从列表里消失（比如 Codex 没登录）再回来，仍然是隐藏的。

## 发送图片和文件

输入框可以给下一条消息附加图片和文件；发送后它们和这条消息一起显示在对话里。

| 做法 | 说明 |
| --- | --- |
| `Ctrl+V` | 粘贴截图（剪贴板里的图片），或在资源管理器里复制的文件，一次可以多个；文字照常粘贴 |
| 📎 按钮（提示「附加文件」） | 选择本地文件，可多选；对话框从当前项目文件夹开始 |
| 拖放 | 把文件或图片拖到输入框，或拖到对话区，效果一样 |

- 每个附件在输入框上方是一张卡片：图片显示缩略图，其他文件显示带类型的图标；下面是文件名和大小，点「×」移除，点缩略图看大图。同名文件会自动改成 `名字 (2)`。
- 只有附件、没有文字也能发送，发出去的文字是「请查看附件。」。
- 回合还在运行时可以先附加、先写下一条，等这一轮结束再发；切换标签页不会丢。
- 带附件的消息发送失败（比如 Droid 拒绝了某个附件）时，对话里会说明原因，文字和附件放回输入框，直接再按一次 Enter 重试。
- 发出去的消息在对话里带着缩略图和文件卡片，点缩略图是大图；从侧边栏恢复的历史会话里也是一样。

| 类型 | 发给模型的方式 | 限制 |
| --- | --- | --- |
| PNG / JPEG / GIF / WebP（按内容判断，不看扩展名） | 原样作为图片 | 5 MiB、长边 8000 像素以内；更大的会自动缩小（长边不超过 2048 像素）并重新压缩，卡片上标「已压缩」 |
| 其他能解码的图片（BMP、TIFF、剪贴板里的位图……） | 转成 PNG 作为图片 | 同上 |
| PDF | 作为文档，同时附上用 Qt 提取出的文字（给没有原生 PDF 支持的模型用） | 3 MiB |
| 文本和源码（`.txt`、`.md`、`.py`、`.json`……；没有扩展名但内容是干净的 UTF-8 / UTF-16 也行；GBK 等旧编码会标「按 … 读取」） | 作为文档，直接发文字 | 1 MiB |
| 其他二进制文件（压缩包、可执行文件、Office 文件）、文件夹 | 不发送：说明原因，并可点「在提示词中插入路径」，让模型自己用工具去读 | |

一条消息通常带 10 个附件、合计 20 MiB 以内；多带也可以，不会替你少带：加附件时状态栏会说「现在比一条消息通常带的量多 N 个文件…，发送时会让你确认」，点发送时会弹出对话框写明超了多少，你点「仍然发送」才发（`Enter` 不会替你确认）。只有多到 50 个或 200 MiB 才直接拒绝，多半是误操作；单个文件另有大小限制（图片超过 5 MiB 会自动压缩，PDF 不超过 3 MiB），被拒绝的文件会在输入框上方说明原因，其余的照常附加。当前模型已知不支持图片输入时，带图片的消息在发送前就会被拦下并提示（否则 Droid 会悄悄把图片换成一句说明，看上去像是模型无视了图片）。消息发送失败时，它的附件会全部放回输入框，哪怕输入框这时又加了新的也不会丢；超过通常量时状态栏会写明超了多少，重试时再让你确认。WittyCode 自己不把附件写到磁盘，只把数据交给 droid；droid 会把它们存进会话记录，并在自己的目录里留拷贝。

## 窗口的边界

窗口没有系统标题栏（标题栏是页面自己画的），所以在 Windows 上单独给它加了两样东西，白色窗口叠在白色窗口上也看得清边界：一是系统自己的阴影（Windows 11 上同时是圆角），二是页面画的一圈 1 px 细线（亮 / 暗主题各有颜色，最大化时不画）。阴影靠 `desktop/ui/winframe.py` 向 Windows 要，页面仍然占满整个窗口，移动、缩放、贴边照旧；不是 Windows 窗口时（比如测试用的离屏平台）两样都没有。
