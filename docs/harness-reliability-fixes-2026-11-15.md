## 长输出边界

- 引用是 `o-<SHA-256>`，不是路径；只读当前原生会话的输出库。读取时检查内容哈希、UTF-8 和大小，拒绝链接／重解析目录等已发现的越界情形。
- 单份输出最多 16 MiB，会话总量最多 256 MiB、4,096 份。配额不足暂停，不自动删掉旧证据。这些是产物存储上限，不是整个会话历史的内存上限。Shell 达到输出保留上限会停止命令并明确标为部分输出，不能据此认定命令完成。
- 产物写入和校验在工作线程中进行；取消时等待正在进行的原子保存收尾，不重新执行工具。保存失败仍保留现场可查看的结果，但不继续请求模型。
- 永久删除会话时清理该会话的产物，不进入其他会话。损坏或缺失的引用不会被静默重建成假原文。
- 已经在旧版本存档中丢失的字符无法还原；这不是旧数据修复器。分页工具自身没有返回的文件内容也不被虚构成已保留证据。
- 页面原有输出展示上限没有扩大；完整原始结果由引用读取和摘要恢复，不依赖页面预览充当唯一存档。

## 旁路计量与性能

标题请求的服务端 usage 计入所属会话和实际使用的模型，但不改变主会话的上下文占用和生成速度。没有可写的活动会话时，旁路 usage 进入独立本地账本，避免用已关闭控制器的旧快照覆盖存档；独立账本不回填已关闭会话的 UI 合计。没有服务端用量时不凭空估算账单；这仍不是跨进程、跨设备的计费系统。

普通 HTTP 和 Bedrock 请求的 JSON 编码移到工作线程。长工具结果采用“完整产物写一次，检查点保存引用”的方式，避免每次重新编码相同的大段文本。其余会话元数据仍使用原子 JSON 快照，**没有宣称已经实现通用追加日志或消除所有同步保存开销**。

页面只对未变化的大块内容发送引用，前端复用原块。首次发送、整页刷新、版本不匹配都发送完整块；用于落盘的缓存快照不能冒充页面已收到的版本。普通小块仍直接发送，避免不必要的增量协议开销。

五次重复保存的本地合成微基准：约 30 MiB 的十份工具结果，原文内联检查点中位数 **78.825 ms／31,458,155 字节**，使用已保留的引用后 **4.546 ms／16,665 字节**。一字符更新旁边的 30K 输出块，事件由 **30,122 字节降为 113 字节**。不包括首次产物写入成本，不代表所有会话、所有磁盘或真实模型的收益。
